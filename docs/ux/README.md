# Production UX program

This directory governs the incremental redesign of the public application. The goal is a coherent, accessible experience built on production behavior—not a wholesale import of the Lovable prototype.

## Authority order

When sources disagree, use this order:

1. Production backend contracts, domain rules, and compliance requirements.
2. `CAPABILITY-STATUS.md` for what may ship now.
3. `DESIGN-SYSTEM.md` for visual and interaction decisions.
4. `ACCEPTANCE-GATES.md` for approval evidence.
5. Mountain Bloom prototype for the visual anchor and interaction inspiration; its mock behavior does not override production contracts.

## Documents

- `DESIGN-SYSTEM.md` — production visual language and component decision rules.
- `CAPABILITY-STATUS.md` — stable capability IDs and prototype-only decisions.
- `ACCEPTANCE-GATES.md` — non-negotiable gates for every redesigned journey.
- `EXECUTION-AND-HANDOFF.md` — sequence, ownership boundaries, and handoff format.
- `PILOT-HANDOFF.md` — implemented discovery pilot, capability/route mapping, evidence, and remaining gates.
- `future-concepts/PATIENT-GUIDANCE.md` — parked concept; not part of the current site.

## Current pilot

The first production journey is discovery through product evaluation: search, filters, results, variants, price comparison, reviews, and external dispensary handoff.
